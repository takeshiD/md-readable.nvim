# [I06] SUMMARY構文の解析

## 目的

ネスト、部タイトル、リンク、draft相当の構文と原文位置を保持。SSG固有の意味はadapterで決定。

## 入出力と対象範囲

SUMMARYのMarkdownとpath → 順序・階層・タイトル・リンク・リンクなし項目・source位置。

SSG検出・draftの意味決定・ファイル移動はしない。

## 先行Issue

- I00（起票時にGitHubリンクへ置換）

先行は結合完了に必要な依存を表す。I00完了後は契約fixtureで先行実装できるが、モックだけで依存との結合確認を済ませない。

## 担当ファイル

lua/md-readable/parsers/summary.lua

専用テスト・fixture: `tests/i06/`。公開入口、設定、コマンド、README/helpの接続はI27へ引き継ぎ、この担当から同時編集しない。 共通契約を変える場合は統合担当と先に調整する。

## 受け入れ条件

- [ ] ネスト、部タイトル、前後の章、空リンク、空白・日本語path、anchorを順序通り抽出する。
- [ ] リンクタイトルと参照先を混同せず、draft等の意味付けに必要な構文を失わない。
- [ ] mdBook/HonKit/GitBookの差はadapterで決められる中立な結果を返す。

## 検証と引き継ぎ

対象のheadlessテストと関連する結合テストを実行し、実行コマンド・結果・未確認点を記載する。端末画像等の実表示が必要な場合は手動検証を区別し、実施していない結果を成功と記載しない。追加する設定・コマンド・任意依存とcleanup契約をI27へ引き継ぐ。

仕様根拠: `md-readable_design.md`、`docs/final-spec-review.md`、`docs/implementation-issues.md`。4参考プラグインへの必須依存で実装を代用しない。別のworktreeで作業し、担当外の変更を上書きしない。
