# [I01] Markdown構造の抽出

## 目的

ATX/Setext、code内見出し除外、reference link、escaped pipe、inline code、日本語の原文範囲が正しい。

## 入出力と対象範囲

未保存内容を含む原文とchangedtick → DocumentSnapshot。拡張構文の追加口も定義し、I25が本ファイルを変更せず登録できるようにする。

描画・ファイル書き換え・ウィンドウ操作はしない。

## 先行Issue

- I00（起票時にGitHubリンクへ置換）

先行は結合完了に必要な依存を表す。I00完了後は契約fixtureで先行実装できるが、モックだけで依存との結合確認を済ませない。

## 担当ファイル

lua/md-readable/document/{parser,outline,links,blocks,table}.lua

専用テスト・fixture: `tests/i01/`。公開入口、設定、コマンド、README/helpの接続はI27へ引き継ぎ、この担当から同時編集しない。 共通契約を変える場合は統合担当と先に調整する。

## 受け入れ条件

- [ ] ATX/Setext、レベル飛び、同名見出し、日本語、frontmatter、fenced code内の#を区別する。
- [ ] inline/reference link、同一ページanchor、外部URL、asset、未解決参照を範囲付きで抽出する。
- [ ] 表のescaped pipe、inline code、任意の前後pipe、alignment、全角・結合文字を同一parserで扱う。表示用と整形用に別parserを作らない。
- [ ] 標準Markdown/GFMのリスト・引用・コード・強調・取消線・task listを範囲付きで保持し、構文対応一覧をfixtureに対応させる。

## 検証と引き継ぎ

対象のheadlessテストと関連する結合テストを実行し、実行コマンド・結果・未確認点を記載する。端末画像等の実表示が必要な場合は手動検証を区別し、実施していない結果を成功と記載しない。追加する設定・コマンド・任意依存とcleanup契約をI27へ引き継ぐ。

仕様根拠: `md-readable_design.md`、`docs/final-spec-review.md`、`docs/implementation-issues.md`。4参考プラグインへの必須依存で実装を代用しない。別のworktreeで作業し、担当外の変更を上書きしない。
