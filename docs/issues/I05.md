# [I05] 宣言的設定の解析

## 目的

順序・ネスト・診断位置を保持し、未対応構文を成功に見せかけない。基本利用にNode/Python不要。

## 入出力と対象範囲

設定テキストとsource path → 順序とsource範囲を保持した設定値、診断、依存ファイル情報。

SSGごとのdocs_dir等の意味はadapter側。

## 先行Issue

- [I00 #1](https://github.com/takeshiD/md-readable.nvim/issues/1)

先行は結合完了に必要な依存を表す。I00完了後は契約fixtureで先行実装できるが、モックだけで依存との結合確認を済ませない。

## 担当ファイル

lua/md-readable/parsers/{yaml,toml,frontmatter}.lua

専用テスト・fixture: `tests/i05/`。公開入口、設定、コマンド、README/helpの接続はI27へ引き継ぎ、この担当から同時編集しない。 共通契約を変える場合は統合担当と先に調整する。

## 受け入れ条件

- [ ] 対象navのネスト配列/辞書、文字列、コメント、quoted keyをfixtureで扱い、順序をtable走査で失わない。
- [ ] 対象外のYAMLタグ、継承、動的値等を黙って捨てず、診断する。対応する具体的な構文を一覧化する。
- [ ] 正規表現だけでネストを解析しない。採用parserの対応範囲・ライセンス・導入方法を記録し、基本利用にNode/Pythonを要求しない。

## 検証と引き継ぎ

対象のheadlessテストと関連する結合テストを実行し、実行コマンド・結果・未確認点を記載する。端末画像等の実表示が必要な場合は手動検証を区別し、実施していない結果を成功と記載しない。追加する設定・コマンド・任意依存とcleanup契約をI27へ引き継ぐ。

仕様根拠: `md-readable_design.md`、`docs/final-spec-review.md`、`docs/implementation-issues.md`。4参考プラグインへの必須依存で実装を代用しない。別のworktreeで作業し、担当外の変更を上書きしない。
