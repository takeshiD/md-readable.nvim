# 最終仕様確認

状態: 2026-10-03、Q22で初期値を含めて承認済み。GitHubに実装32件＋全体追跡1件を起票し、並列実装を進める。

## 合意した製品と必須範囲

- 他人のMarkdownとSSGの書籍を読む用途を主役とし、画像・図を含む完成した文書に近い表示を目指す。
- 元のREADME・設計書の機能はすべて実装する。SSGはmdBook / HonKit / GitBook / MkDocs / Zensical / Docusaurus / Astroの7対象。ローカルの静的設定を標準対応とし、動的生成は明示provider経由とする。
- 同じwindow、左右分割、floatingの読書表示をコマンドで提供する。原文の未保存編集を反映し、カーソル・ページ移動を双方向同期する。
- ナビゲーションは3配置をconfigで選べる。既定は左側の統合ツリー、ミニマップは非表示から開閉する。
- FocusはLimelightの段落追従・選択行固定・減光設定を再現し、読書表示だけに適用する。テーマ切り替えも読書表示だけ。
- 表は長いセルを省略し、全文確認を可能にする。原文の整形と行・列の挿入削除は明示操作で提供する。
- `/`は表示テキストの通常検索。原文検索は専用コマンド。`y`は原文コピーで、リンクの一部を選ぶとその文字列、ラベル全体を選ぶとMarkdownリンク全体になる。
- 対応環境では画面内の画像・Mermaidを自動表示する。外部画像の取得は操作または設定で許可するまで行わない。
- Telescope / Snacksのpreview連携、ミニマップのGit差分・LSP診断表示も必須。
- 4参考プラグインを必須依存にしない。機能は内蔵する。画像変換・Mermaid・picker等の任意依存がなくても基本機能は動く。
- Neovim終了をまたぐ読書位置保存は不要。動画・PlantUML・CSV変換・数式計算は今回の追加範囲に含めない。

## 合意した初期値

### コマンドと終了

| 操作 | 初期動作 |
| --- | --- |
| `MdReadable` | 現在のwindowで原文を読書表示へ切り替える |
| `MdReadable vert` | 原文を残して右側に読書表示を開く |
| `MdReadable float` | 原文を残してfloatingの読書表示を開く |
| `MdReadable source` | 対応する原文と位置へ移動する |
| `MdReadable close` | 対象の読書表示を閉じる。同一window方式なら原文へ戻す。原文bufferは破棄しない |
| 同じ起点・同じ表示方式で再実行 | 既存の読書表示を再利用して移動する。重複windowを増やさない |

目次・見出し・前後ページ・リンク・原文検索・Focus・テーマ・ミニマップ・表操作等にもサブコマンドとLua APIを提供する。設定可能な補助キーマップはopt-inとし、原文の標準キーは変えない。読書bufferの`y`だけは合意した原文コピーに必要な動作を提供する。

### コピーの境界

- 省略セルの`…`を含めた選択は、その元セル全体をコピーする。省略されていない部分だけの選択は対応する原文部分をコピーする。
- 表の罫線や画像用の空き行など、表示専用の装飾だけを選んだ場合は原文がないことを示し、レジスタを変更しない。
- reference-style linkは元の参照記法を保持し、インラインリンクへ変換しない。選択外の参照定義を勝手に追加しない。
- 行単位のコピーは対応する原文行を重複なく取り出す。折返しで複数表示行が同じ原文行へ対応しても二重コピーしない。通常の文字選択・行選択・矩形選択・指定レジスタをテスト対象にする。

### 初期の拡張記法

標準Markdown/GFM相当の本文に加えて、GitHub形式のalert、Obsidian形式のcallout、HTMLの`details`/`summary`、Docusaurus形式の静的admonition、MkDocs形式の静的admonitionを初期対象とする。タブは静的なDocusaurus `Tabs`/`Tab`とMkDocs系の`===`見出しを対象にし、コードやコンポーネントは実行しない。

初期対応する構文と制限をfixture・helpに列挙する。未対応形式は原文を確認できるようにし、表示の細部は最初の実装を見て調整する。独自JavaScript、任意HTML/CSS、サイト固有コンポーネントの実行は行わない。

### ミニマップの入力

- 読書表示の縮小表現を対象にし、現在行を表示する。Braille表示を基本とし、文字を表示できない場合は簡略表示を選べるようにする。
- GitはGitコマンドを利用する内蔵providerを用意し、既定ではindexと未保存編集を含む原文bufferを比較する。gitsigns等の導入を必須にしない。追加・変更・削除を区別する。
- 診断は原文bufferのNeovim標準診断を利用し、ERROR/WARN/INFO/HINTとseverity filterを扱う。複数診断が重なる場合は重大度の高いものを優先し、Git差分とは区別する。
- Gitや診断情報がない場合もミニマップ本体は使える。情報はSourceMapを通して読書表示へ対応付ける。

### 任意依存と画像

外部ツールはユーザーが導入したもの、または明示設定したものを使う。不在時に自動インストールや`npx -y`による取得はしない。Mermaidは元コード、画像はalt text等を残し、healthで不足を確認できるようにする。

画像の初期検証対象はREADMEにあるWezTerm / Ghostty。複数の読書window、floating、resize、scroll、close、pickerの高速切り替えで描画が残留しないことを確認する。対応する画像表示環境でも、制限が残る構成は検証結果として明記する。

## Issueと完了条件

[全体追跡Issue案](issues/TRACK.md)から実装32件の本文を参照できる。各Issueに先行関係、担当ファイル、入力・出力、受け入れ例、検証方法を記載する。公開入口・設定・コマンド・README/helpの共有編集は統合担当が管理する。

全機能が接続され、対応表・headlessテスト・端末での確認結果・導入手順が揃って完成とする。基盤だけ、mdBookだけ、あるいは外部プラグインの導入案内だけでは完了としない。
