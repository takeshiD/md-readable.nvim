# [I03] 基本読書レンダリング

## 目的

表示を再生成しても原文を変えず、言語別コード色付けとparser不在時の平文表示が成立。

## 入出力と対象範囲

DocumentSnapshotと表示幅・描画設定 → RenderedDocument。表・拡張構文・画像は共通dispatcherへ別担当のrenderer/providerを登録できるようにする。

表・画像・Mermaid・拡張記法・テーマの実装は専用Issue。

## 先行Issue

- [I01 #2](https://github.com/takeshiD/md-readable.nvim/issues/2)
- [I02 #3](https://github.com/takeshiD/md-readable.nvim/issues/3)

先行は結合完了に必要な依存を表す。I00完了後は契約fixtureで先行実装できるが、モックだけで依存との結合確認を済ませない。

## 担当ファイル

lua/md-readable/reader/render.lua、lua/md-readable/renderers/{text,inline,code}.lua

専用テスト・fixture: `tests/i03/`。公開入口、設定、コマンド、README/helpの接続はI27へ引き継ぎ、この担当から同時編集しない。 共通契約を変える場合は統合担当と先に調整する。

## 受け入れ条件

- [ ] 見出し、段落、入れ子リスト/引用、強調、取消線、inline code、リンク、task list、コードを整形表示し、原文とSourceMapを保持する。
- [ ] コードの利用可能な言語parser/syntaxを使い、不在時もコード本文を失わない。
- [ ] 長いURLを省略してもhost等の手掛かりと全文確認用データを保持する。通常の日本語・全角・結合文字・tabを幅計算で壊さない。
- [ ] 80列/120列、再描画、折返し、空文書で動作し、原文の変更なし。

## 検証と引き継ぎ

対象のheadlessテストと関連する結合テストを実行し、実行コマンド・結果・未確認点を記載する。端末画像等の実表示が必要な場合は手動検証を区別し、実施していない結果を成功と記載しない。追加する設定・コマンド・任意依存とcleanup契約をI27へ引き継ぐ。

仕様根拠: `md-readable_design.md`、`docs/final-spec-review.md`、`docs/implementation-issues.md`。4参考プラグインへの必須依存で実装を代用しない。別のworktreeで作業し、担当外の変更を上書きしない。
