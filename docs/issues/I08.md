# [I08] mdBook対応

## 目的

book.toml、source root、SUMMARYの順序・階層・draftから実在文書へ移動可能。

## 入出力と対象範囲

book.tomlとsource SUMMARY → NavigationSnapshot/diagnostics/dependencies。

共通parserを独自複製しない。

## 先行Issue

- [I04 #5](https://github.com/takeshiD/md-readable.nvim/issues/5)
- [I05 #6](https://github.com/takeshiD/md-readable.nvim/issues/6)
- [I06 #7](https://github.com/takeshiD/md-readable.nvim/issues/7)

先行は結合完了に必要な依存を表す。I00完了後は契約fixtureで先行実装できるが、モックだけで依存との結合確認を済ませない。

## 担当ファイル

lua/md-readable/adapters/mdbook.lua

専用テスト・fixture: `tests/i08/`。公開入口、設定、コマンド、README/helpの接続はI27へ引き継ぎ、この担当から同時編集しない。 共通契約を変える場合は統合担当と先に調整する。

## 受け入れ条件

- [ ] source root変更、部タイトル、ネスト、前書き/後書き、draft、不在ファイルをfixtureで検証する。
- [ ] 親ページ・子ページの順序と実在文書への対応を共通coreで確認する。
- [ ] preprocessor生成結果の扱いを明記し、未対応設定を完全対応と宣言しない。
- [ ] 対象設定の具体的な構文・非対応構文・確認した公式資料と版を記録し、正常系/未対応/root変更/順序/実在文書への対応のfixtureを揃える。名前だけの対応は完了としない。

## 検証と引き継ぎ

対象のheadlessテストと関連する結合テストを実行し、実行コマンド・結果・未確認点を記載する。端末画像等の実表示が必要な場合は手動検証を区別し、実施していない結果を成功と記載しない。追加する設定・コマンド・任意依存とcleanup契約をI27へ引き継ぐ。

仕様根拠: `md-readable_design.md`、`docs/final-spec-review.md`、`docs/implementation-issues.md`。4参考プラグインへの必須依存で実装を代用しない。別のworktreeで作業し、担当外の変更を上書きしない。
