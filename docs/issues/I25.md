# [I25] 一般的な拡張記法

## 目的

初期対象構文を列挙してfixtureで検証し、独自コンポーネントは原文確認可能。初期実装後の調整点を記録。

## 入出力と対象範囲

原文の静的拡張構文 → 共通Document要素と原文範囲付き描画。

任意HTML/MDXの完全実行はしない。

## 先行Issue

- [I01 #2](https://github.com/takeshiD/md-readable.nvim/issues/2)
- [I02 #3](https://github.com/takeshiD/md-readable.nvim/issues/3)
- [I03 #4](https://github.com/takeshiD/md-readable.nvim/issues/4)

先行は結合完了に必要な依存を表す。I00完了後は契約fixtureで先行実装できるが、モックだけで依存との結合確認を済ませない。

## 担当ファイル

lua/md-readable/document/extensions.lua、lua/md-readable/renderers/extensions.lua

専用テスト・fixture: `tests/i25/`。公開入口、設定、コマンド、README/helpの接続はI27へ引き継ぎ、この担当から同時編集しない。 共通契約を変える場合は統合担当と先に調整する。

## 受け入れ条件

- [ ] GitHub alert、Obsidian callout、details/summary、静的Docusaurus/MkDocs admonitionの対象構文をfixture化する。
- [ ] 静的Tabs/Tabと===形式のタブを切り替え、隠れた本文の原文対応を保持する。
- [ ] 未知の構文・独自コンポーネントを空白にせず原文確認可能にし、JS/CSSを実行しない。
- [ ] 初期実装の表示例を残し、ユーザーが後で見た目を調整できるよう設定と対応制限を記録する。

## 検証と引き継ぎ

対象のheadlessテストと関連する結合テストを実行し、実行コマンド・結果・未確認点を記載する。端末画像等の実表示が必要な場合は手動検証を区別し、実施していない結果を成功と記載しない。追加する設定・コマンド・任意依存とcleanup契約をI27へ引き継ぐ。

仕様根拠: `md-readable_design.md`、`docs/final-spec-review.md`、`docs/implementation-issues.md`。4参考プラグインへの必須依存で実装を代用しない。別のworktreeで作業し、担当外の変更を上書きしない。

全体追跡: https://github.com/takeshiD/md-readable.nvim/issues/33
